# 豆包客户端视觉 OCR 基线（V2）

## 结论

豆包客户端在 5 张测试图片上正确识别了全部开票日期和价税合计，也识别出其中 1 组完全重复的图片；发票号码正确 2/5，但这两条来自同一张重复图片，按不同票据计算仅正确 1/4，因此不能驱动自动审核，自动放行率保持为 0%。

| 关键字段 | Tesseract V1 | 豆包客户端 V2 |
| --- | ---: | ---: |
| 发票号码 | 4/5 | 2/5 |
| 开票日期 | 2/5 | 5/5 |
| 价税合计 | 5/5 | 5/5 |
| 三字段全部正确 | 2/5 | 2/5 |

## 关键 Bad Case

视觉模型能够输出格式完整、语气确定的长票号，但在 3 张不同票据的连续数字中插入额外的 `0`。这说明格式完整和语气确定不能替代二维码结构化字段、黄金集评测或票面验真。

## 评测方法

- 样本：5 张用户提供的测试图片，其中 2 张为完全相同的图片，共 4 张不同票据。
- 运行方式：豆包桌面客户端，逐图人工上传；不是 API 集成或自动化生产链路。
- 字段：发票号码、开票日期、价税合计。
- 隐私：真实字段与客户端结果只保存在本地 `work` 目录；公开文件只保留匿名编号和对错。

## 产品决策

V2 只作为辅助识别层：日期和金额可预填，发票号码必须通过二维码、结构化电子票源或人工逐字符确认。任一关键字段未验证时转人工，不执行自动放行。

本结果只是 5 张图片的探索性基线，不能外推为线上准确率，也不能证明联网验真、红冲、作废或假票识别能力。
