# 现有 Workflow 能力审计

## 已实现

- 支持图片文件上传；
- 统计上传文件数量；
- 调用大模型尝试提取发票号码、日期、项目名称、金额等字段；
- 在本次上传批次中按“发票号码”统计重复；
- 输出简单文字结果。

## 关键限制

1. 条件分支写死为上传数量等于 3，其他数量均提示“请上传多张发票”；
2. 模型节点配置中视觉能力关闭，图片识别链路需要重新验证；
3. 只按发票号码判断重复，没有文件哈希、发票代码或组合字段；
4. 没有读取历史报销台账；
5. 没有真伪、红冲、作废状态查询；
6. 没有人工复核状态、审核人、审核时间或审计留痕；
7. Prompt 说“所有信息必须准确无误”，但没有置信度、缺失字段或冲突处理；
8. 报告中的“当前已实现历史台账查重、假票与红冲识别”与 Workflow 不一致。

## 本阶段修正

先把查重判断从大模型中剥离，做成可复现的确定性规则：

| 规则 | 判断 | 产品动作 |
|---|---|---|
| R00 | 日期或金额无效 | 人工复核 |
| R01 | 发票号码缺失 | 人工复核 |
| R10 | 本批次文件哈希相同 | 暂停入账并人工复核 |
| R11 | 本批次发票代码+号码相同 | 暂停入账并人工复核 |
| R20 | 与历史台账发票代码+号码相同 | 暂停入账并人工复核 |
| R30 | 同销售方、同金额、日期相差不超过 3 天，但号码不同 | 疑似重复，人工复核 |

R30 只表示“值得复核”，不能当作重复报销的最终结论。
